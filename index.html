同一套文件格式

单篇文件自带全部信息，不依赖索引文件：标题、文件夹、标签、置顶、废纸篓与时间戳都写在文件开头，其后为 Markdown 正文。

同一份操作日志

桌面端与网页端读写的是同一份服务端日志，同一批数据可在两端之间互相接管。

一台进程两种角色

03设计

两个核心设计

本地优先决定了数据放在哪里，操作日志决定了同步如何表达删除。两者共同决定了这套实现与 「文件快照 + 目录对比」类同步的差别。

本地优先

数据目录即全部状态。不存在账号，不存在服务端侧的笔记副本，也不存在以服务端为准的隐式上传。

  • 笔记与待办以 .md 落在 notes/ 与 todos/，AI 对话以一份对话一个 JSON 文件落在 ai_chats/。
  • 密钥类内容（AI Key、同步令牌）不进数据目录，交由系统密钥链单独保管，备份、迁移或分享数据目录都不会带出密钥。
  • 复制整个数据目录即完成一次备份，用 Git 初始化即获得完整历史版本。

操作日志同步

同步以「操作（put / del）」为单位追加到服务端日志，客户端只记录「已应用到第几号」。

  • 同步过程为「拉取序号之后的操作并重放 + 推送本地改动」，删除是一条明确的删除标记，重放只会删除，不会反向产生写回。
  • 条目被彻底删除后，服务端抹掉其正文与历史，只留一行删除标记，并把它作为可复用 ID 收进回收池供后续新建使用。
  • 其余操作的序号不动，各设备记的「已应用到第几号」因此照旧有效。
同步模型 客户端可见信息 删除的后果
文件快照 + 目录对比 远端存在 / 不存在某文件 「删除」与「从未见过」不可区分，其他设备会把本地缺失视为待上传，从而重新生成该文件
操作日志（本项目） 逐条 put / del 操作及其全局序号 删除是一条明确的删除标记，重放只会删除，不会反向产生写回

04上手

三条路径

三条路径互不依赖：只用桌面客户端即可离线写作；需要多设备同步时再部署服务端； 网页客户端由服务端托管，也可以在无服务端时以本地模式打开。

03

使用网页客户端

已部署在 esprinnemo.pages.dev，无需安装； 该地址不接服务端，以本地模式运行（界面与本地副本照常，同步整套不出现）。需要跨设备同步时，由自建服务端在根路径托管同一份界面。
